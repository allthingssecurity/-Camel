## What is specified (and nothing more)

A program is the context's autoStartup and 1-4 routes `from("direct:<id>")` with an id, an optional startupOrder and an
autoStartup flag. Operations: context start / stop / suspend / resume; RouteController startRoute / stopRoute /
suspendRoute / resumeRoute / startAllRoutes / stopAllRoutes; CamelContext.removeRoute; a message to `direct:<id>`
(`block=false`, or `block=true&timeout=100`). Observed after every operation: result (no exception / boolean / exception
class / message routed or failed), the RouteStarted / RouteStopped / RouteRemoved events of the operation (order
compared, with per-rule "ignored" events where the docs are silent), the context status, every route's status.

- Rules: the relation `lstep` (25 tagged rules: 19 DOC, 3 CODE = the Real-mode deltas of one finding, 2 FIX, 1 DOC-BUG),
  `ltrace`; the interpreter `step` / `run_ops`; theorems `step_sound`, `step_complete` (so the rules are deterministic
  for given real/sus), `run_sound`, `stop_reverses_start` (a stop right after the start stops in the reverse order of the
  start events) with 10 helper lemmas; non-vacuity examples for `stop_reverses_start` and `run_sound`; 9 documented
  examples (`doc_*`, vm_compute) and the finding's reproducer `real_restart_clash` (Doc vs Real).
- Not covered: route policies, supervising route controller, graceful-shutdown timeouts with in-flight exchanges,
  ShutdownRoute/ShutdownRunningTask, addRoutes on a started context, reload, route groups, stopRoute with timeout /
  abortAfterTimeout, stopRoute(id, cause), removeAllRoutes, shutdown(), components other than direct, polling consumers,
  endpoint/component/producer lifecycle.
- `sus` (does the direct consumer support suspension?) is not documented: the oracle prints both traces; a case agrees
  when Camel matches one. Camel matched only `sus = true` (or both) in every run: the `sus = false` constructors
  (LSuspendN, LResumeN, LRSuspendN, LRResumeN, LRResumeNClash) are allowed by the docs but never seen (strictness
  note, CONVENTIONS practice 1); DirectConsumer suspends.

mismatch .. setup-error .. unspec-cases .." then the UNSPECIFIED reasons), `.l4hits` (rule id, hits of compared
operations, both sus alternatives), `.mism.tsv`, `.unspec.tsv` (at most 50 examples per reason with what Camel did),
`L4-ORACLE-BUILD-INFO`, `MODE`. The `guided` family picks each operation among random candidates so that the rules
(Doc, sus=true) do not call it UNSPECIFIED (the driver asks the extracted rules; it adds no semantics).

## Rules never hit

None: every one of the 25 rule ids has compared hits in Doc and Real runs (`.l4hits`). Caveats: hits are counted for
both sus alternatives, and the sus=false constructors were never the alternative Camel matched; LRResumeNClash shares
its hit id with LRStartClash (`L4.route.start.clash.real`) and can only occur with sus=false, so it is effectively
never exercised.

- L4.ctx.stop / L4.ctx.stop.cleared: route statuses after a context stop "Stopped" -> not documented (?), RouteRemoved
  events of the stop ignored; FIX (CCJ.77-78 "clear internal state/cache" does not say the routes stay; Camel removes
  them: getRoute null, RouteRemovedEvent; runs/l4-try first 50 cases).
- L4.stop.reverse-order: reverse of the chronological order of the start operations -> reverse of the startup order
  numbers; DOC-BUG (doc-bug entry below; Camel: DefaultShutdownStrategy.doShutdown and AbstractCamelContext.stopAllRoutes

  SDJ.31-34, RSJ.29-31 say the same).
- L4.ctx.start.clash: FailedToStartRouteException only when every clashing route is auto-started -> on any clash among
  all routes (context autoStartup true); FIX (CFG.183 "unique among all routes in your CamelContext"; Camel: 142 of 142
  recorded cases).
- New Real-mode deltas L4.order.renumber.real, L4.route.start.clash.real, L4.rc.startAll.clash.real; CODE, finding
  2026-10-26-l4-startuporder-renumbered-on-restart.md.

## Doc bugs (for findings/doc-bugs.md)

- configuring-route-startup-ordering-and-autostartup.adoc 209 and 438, graceful-shutdown.adoc 18: "stop the routes in
  the *reverse* order that they were started" reads as the reverse of the order in which the routes were started; Camel
  stops in the reverse of their startupOrder numbers, which differs as soon as a route is started on its own after the
  context start (startRoute / startAllRoutes). Suggested wording: "in the reverse order of their startup order (the
  order in which Camel starts them at startup)", as graceful-shutdown.adoc 138-139 already says.
- (with the finding) configuring-route-startup-ordering-and-autostartup.adoc 188-196: true only for the first start of
  each route; until the finding is fixed, the numbers of routes without startupOrder grow with every restart.

## TRUST (what sits outside the check; for TRUST.md)

1. oracle/l4/driver.ml: the generator (which cases exist; `guided` asks the extracted rules) and the printer of the
   expected text; the extraction of Lifecycle.run_case (theories/L4/LifecycleExtract.v).
2. harness/l4/LifecycleRun.java: the case reader; the program built with the model API (RouteDefinition with routeId,
   startupOrder, autoStartup, and a recording Processor as the only step; the context's setAutoStartup); the shutdown
   strategy timeout set to 1 s (documented option, no exchange is in flight at a stop); route events recorded by an
   EventNotifierSupport added before the start (only RouteStarted / RouteStopped / RouteRemoved, in notification
   order); route status = "-" when getRoute(id) is null, else getRouteController().getRouteStatus(id); context status
   = getStatus(); a message = ProducerTemplate.send to direct:<id>?block=false (or ?block=true&timeout=100), "routed"
   when the processor ran once and the exchange has no exception, "failed" when it has one and the processor did not
   run (the exception class is not compared); each operation runs on a worker thread with a 10 s timeout (HANG).
   The comparison: the expected "ignored" events are dropped from Camel's events before comparing, bag events are
   compared sorted, "?" fields are not compared, and a case agrees when one of the two sus traces matches.
3. harness/l4/probes/CounterProbe.java reads InternalRouteStartupManager.defaultRouteStartupOrder by reflection; it was
   used only to design the Real-mode delta, never in a comparison.
